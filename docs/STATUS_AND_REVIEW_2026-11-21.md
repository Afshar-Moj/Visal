# وضعیت فنی و بازبینی وصال — 2026-11-21

## خلاصه اجرایی

مخزن GitHub وصال وجود دارد و کد واقعی رابط و بخشی از زیرساخت Supabase در آن ثبت شده است؛ اما سرویس هنوز عملیاتی یا منتشر نشده است. مهم‌ترین مانع فعلی، ساخته‌نشدن پروژه Supabase و اجرا نشدن مهاجرت‌های پایگاه داده است. انتشار عمومی نیز عمداً تا زمان آماده‌شدن زیرساخت و بازبینی حقوقی متوقف می‌ماند.

## وضعیت تأییدشده

- مخزن عمومی: `Afshar-Moj/Visal`، شاخه اصلی `main`.
- رابط فارسی و راست‌به‌چپ، پروفایل‌های کاملاً ساختگی و فیلتر محلی در `app.js`.
- فرم ثبت‌نام و ورود ایمیل/گذرواژه در `auth.js` با Supabase Auth آماده شده است.
- فایل `supabase-config.js` هنوز نشانی پروژه و کلید عمومی خالی دارد.
- مهاجرت‌های `0001` تا `0003` در مخزن هستند؛ طبق آخرین تأیید مالک در 2026-11-21، پروژه Supabase هنوز ساخته نشده و هیچ‌یک از مهاجرت‌ها روی پایگاه داده اجرا نشده‌اند.
- گردش‌کار GitHub Pages وجود دارد، اما اجرای شماره 25 در 2026-11-15 در مرحله Configure GitHub Pages با خطای نبودن سایت Pages متوقف شده است. هیچ انتشار موفقی تأیید نشده است.
- قوانین استفاده و سیاست حریم خصوصی فقط پیش‌نویس‌اند.

## اقدام امنیتی این نوبت

در مهاجرت جدید `0004_lock_birth_date.sql` سیاست ویرایش تاریخ تولد توسط کاربر حذف شده است. پس از اجرای این مهاجرت، کاربر عادی نمی‌تواند تاریخ تولد ثبت‌شده را از API تغییر دهد؛ اصلاح اشتباه باید از مسیر پشتیبانی بررسی‌شده انجام شود. این تغییر جعل سن در زمان ثبت‌نام را به‌تنهایی متوقف نمی‌کند؛ تاریخ تولد همچنان خوداظهاری است و برای اثبات سن واقعی، روش متناسب و قانونی لازم خواهد بود.

همچنین بررسی ایستای کد به مخزن افزوده شده تا در هر تغییر، وجود فایل‌های اصلی، نحو JavaScript، فعال‌بودن RLS روی جدول‌ها، جداسازی تاریخ تولد و خصوصی‌ماندن تابع مسدودسازی کنترل شود. این بررسی‌ها جای اجرای SQL روی Supabase یا آزمون نفوذ را نمی‌گیرند.

## گام‌های بعدی به ترتیب

1. مالک پروژه Supabase با نام Visal را ایجاد کند.
2. مهاجرت‌های `0001`، `0002`، `0003` و `0004` به همین ترتیب اجرا شوند.
3. فقط Project URL و کلید عمومی publishable/anon در تنظیمات رابط قرار گیرد؛ کلید service_role/secret نباید در مرورگر یا مخزن قرار گیرد.
4. اتصال ثبت‌نام و ورود آزمایش شود؛ سپس جست‌وجوی سروری، پیام‌رسانی زنده، مسدودسازی، گزارش و پنل رسیدگی ساخته شوند.
5. پیش از انتشار، روش ثبت‌نام مناسب کاربران ایران (ایمیل یا OTP شماره موبایل)، میزبانی و دسترسی از داخل ایران، احراز سن، مسئولیت رسیدگی انسانی و متن‌های حقوقی تعیین و آزمایش شوند.

## توقف انتشار عمومی

گردش‌کار انتشار Pages تا زمانی که مالک Pages را فعال و انتشار را تأیید نکرده، فقط با اجرای دستی قابل فراخوانی است؛ تغییرات معمول کد دیگر تلاش ناموفق برای انتشار ایجاد نمی‌کنند. پس از آماده‌شدن نسخه قابل انتشار، می‌توان انتشار خودکار پس از هر تغییر را دوباره فعال کرد.
